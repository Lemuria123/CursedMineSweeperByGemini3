# 开格重排算法

开格时的诅咒和祈祷都走 `shared/gameLogic.ts` 里的 `rearrangeMines`。前端和服务器复盘共用这一份代码，以及同一个 `mine_seed + '-csp'` 种子。首击布雷 `placeMines` 没有改，仍是均匀抽雷。

## 1. 三条不变量

顶栏剩余雷是 `难度雷数 - 已插旗数`。重排只要成功返回，就必须同时满足：

1. 全盘 `isMine` 的个数与进入函数时相同。
2. `status === 'flagged'` 的格子不改变 `isMine`。
3. 已翻开格子的 `neighborMines` 仍等于周围真实雷数，并且与进入时的数字相同。

任何一条做不到，就恢复进入时的 `isMine` 和 `neighborMines`，函数返回 `false`。诅咒失败时格子保持原样再翻开；祈祷失败时雷留在原格，随后爆炸。

雷数差额只允许用「不挨着已翻开格子」的隐藏格补平：

- 这一步雷变多：只能关掉同样多的孤立雷。
- 这一步雷变少：只能把同样多的孤立安全格改成雷。

池子不够就整步放弃，不能带着差额成功返回。

## 2. 求解

目标格如果已经插旗，雷位钉死，不能翻。

没有已翻开约束时直接交换：诅咒把目标格和一颗孤立雷对调；祈祷走第 3 节的抽样。邻居一旦挨着已翻开数字，就改走约束求解。

约束求解只处理目标格所在的一块。从目标格出发，沿着已翻开格子收集尚未翻开、也没插旗的邻居，上限 50 格。其余连通块保持原样，所以耗时按这一块计算。

每个已翻开数字是一条等式：周围雷数必须仍是原来的数字。求解前先做强制传播：数字已经凑满，未定邻居全是安全；还缺的数量正好等于未定邻居数，那些邻居全是雷。传播不动后再用堆上的显式栈回溯，调用栈保持常数层。单次 `rearrangeMines` 最多展开 4000 个分支，预算用完就回滚。

泛洪在 `revealCellLogic` 里，本身就是堆数组。入栈前先标记，同一格不会从多个空邻居被重复推进。

## 3. 祈祷时的数字

数字永远等于周围真实雷数，不把抽到的整数直接写进格子。

只有 `forceMine === false`、目标格最终是安全格时才抽样。诅咒只尝试把该格变成雷，不为它抽一个数字。

设全局雷密度 `p = 雷数 / 总格数`，该格实际邻居数为 `d`（边缘不到 8）：

- `μ = p × d`
- `σ = sqrt(d × p × (1 - p))`
- 权重 `w(k) = exp(-(k - μ)² / (2σ²))`，`k` 落在不破坏第 1 节的闭区间里

用传入的 `rng` 按权重排出尝试顺序（`key = -ln(U) / w(k)`，key 越小越先试）。先找「周围恰好 k 颗雷」的摆法；这个 k 无解再试下一个。全部失败则回滚。写回后用周围真实雷数回填 `neighborMines`。

σ 接近 0 时，权重集中在离 μ 最近的整数上。

## 4. 不在这次范围内的行为

首击的 3×3 安全区和均匀布雷不变，所以第一下翻开的数字分布仍由 `placeMines` 决定。

已经入库的旧动作如果用这版逻辑重放，诅咒落点可能和当初不同。新对局的客户端与服务器仍是同一条路径。

## 5. 如何核对

在 `server` 目录执行：

```powershell
npx ts-node --transpile-only src/test_csp_invariants.ts
```

脚本覆盖：补不平时的回滚、总雷数、插旗格、已翻开数字、同一种子两次结果一致、祈祷数字落在可行区间并等于回填值，以及 25×25 贴边重排。
